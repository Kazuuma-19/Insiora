# 0008. backend のテスト

## 決定

テストの基盤は Spring Boot に同梱の JUnit、Mockito、AssertJ を使い、DB を使うテストには Testcontainers を採用する。

### 理由

- DB アクセスは SQL を直接書く（[0016](0016-db-access.md)）ため、SQL の誤りは本物の PostgreSQL で動かさないと検出できない
- Flyway のマイグレーション（[0001](0001-db-migration.md)）も、テストのたびに本番と同じ DB で検証できる
- Docker は開発環境ですでに使っている
- DB を起動していないと失敗する今のテストの問題も解消できる

## 比較案

| 案 | 名称 | バージョン | 特徴 | 判定 |
| --- | --- | --- | --- | --- |
| 1 | Testcontainers | 2.0.5（Boot 管理） | 本物の PostgreSQL をコンテナで起動 | 採用 |
| 2 | H2 | — | インメモリ DB | 見送り |

## 案1: Testcontainers

### 概要

テストの実行中に、Docker で本物のミドルウェア（PostgreSQL など）を起動するライブラリ。Spring Boot が公式に対応している。

### メリット

- 本番と同じ DB で検証できる
- Spring Boot の `@ServiceConnection` で、接続設定が自動になる

### デメリット

- テストの実行に Docker が必要
- コンテナの起動に時間がかかる

## 案2: H2（インメモリ DB）

### 概要

Java 製の軽量な DB。メモリ上で動き、テストのたびに作り直せる。

### メリット

- Docker なしで速く動く

### デメリット

- PostgreSQL と SQL の方言が違うため、SQL がテストと本番で同じように動く保証がない
- PostgreSQL 固有の関数を使った集計クエリをテストできない
