# 0001. DB マイグレーション

## 決定

Flyway を採用する。

### 理由

- 使う DB は PostgreSQL だけで、DB に依存しない記述は不要
- SQL をそのまま書けるので、DB アクセス（[0016](0016-db-access.md)）と同じく SQL 中心で統一できる
- Spring Boot の自動設定で、起動時に自動で適用される
- 有償版の機能（ロールバックなど）は、個人開発では必要ない

## 比較案

| 案 | 名称 | バージョン | 特徴 | 判定 |
| --- | --- | --- | --- | --- |
| 1 | Flyway | 12.4.0（Boot 管理） | 連番付きの SQL ファイルで管理 | 採用 |
| 2 | Liquibase | 5.0.4（Boot 管理） | XML / YAML などの changelog で管理 | 見送り |

## 案1: Flyway

### 概要

`V1__create_xxx.sql` のような連番付きの SQL ファイルを、番号順に適用するマイグレーションツール。適用済みのバージョンは DB の履歴テーブルで管理する。

### メリット

- SQL をそのまま書くので、学習コストが低い
- 構成が単純で、Spring Boot の自動設定で起動時に適用される

### デメリット

- ロールバック（undo）など一部の機能は有償版のみ

## 案2: Liquibase

### 概要

変更内容を changelog（XML / YAML / JSON / SQL）に記述し、DB に適用するマイグレーションツール。DB に依存しない記述とロールバックの定義ができる。

### メリット

- DB に依存しない記述ができる
- ロールバックを定義できる

### デメリット

- 記述量が多く、PostgreSQL だけを使う小規模な開発には過剰
- 5.0 でライセンスが変更されたとされ、利用条件の確認が必要
