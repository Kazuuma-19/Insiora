# 0018. ルーティング

## 決定

TanStack Router を採用する。

### 理由

- パス、パスパラメーター、検索パラメーターが型付きで、リンクの間違いがコンパイル時に分かる
- 分析画面では期間、プロジェクト、タグなどの条件が多く、検索パラメーターを型付きで検証・管理できる利点が大きい
- 条件を URL に持たせるので、画面の状態をブックマークや共有で再現でき、クライアントの状態管理が少なくて済む
- 同じ TanStack の TanStack Query と連携し、`loader` でキャッシュを先読みできる
- Vite のプラグインで、ルートの型定義が自動で生成される

## 案1: TanStack Router

### 概要

TanStack 製の、型安全を重視した React 向けのルーター。ファイルベースとコードベースのどちらでもルートを定義でき、検索パラメーターの検証や、ルートごとのデータの先読みができる。

### メリット

- パスと検索パラメーターが型付きで、リンクの間違いがコンパイル時に分かる
- 検索パラメーターを Zod などで検証でき、URL を状態として扱いやすい
- TanStack Query と連携して、`loader` でデータを先読みできる
- 公式の DevTools がある

### デメリット

- React Router より利用者と情報が少ない
- ファイルベースのルーティングでは、生成されるルートの定義ファイル（`routeTree.gen.ts`）を扱う必要がある

## 案2: React Router

### 概要

React で最も広く使われているルーター。v7 以降は Remix の機能を取り込み、データの取得やフレームワークとしての使い方もできる。

### メリット

- 利用者と情報が最も多い
- `loader` や `action` でデータの取得と更新ができる

### デメリット

- 検索パラメーターの型付けや検証は、自分で用意する必要がある
- フレームワークとしての使い方とライブラリとしての使い方があり、構成の選択肢が多い

## 案3: Wouter

### 概要

フックを中心にした、非常に小さいルーター。

### メリット

- 非常に軽く、API が単純

### デメリット

- 型付きのルートやデータの先読みなどの機能がない
- 画面や条件が増えると、自分で用意するものが多くなる
