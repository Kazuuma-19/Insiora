# 0020. UI コンポーネント

## 決定

UI コンポーネントのライブラリは使わない。

### 理由

- Insiora の画面は、グラフ、集計の表、期間やフィルターの選択が中心で、複雑な部品は多くない
- ライブラリの見た目や設計の制約を受けずに、画面を自由に作れる
- 依存関係が増えず、ライブラリの破壊的変更への追従が要らない
- HTML 標準の `<dialog>` や Popover API で、モーダルやポップオーバーの基本的な動作（フォーカスの管理、Esc で閉じるなど）が得られる

## 比較案

| 案 | 名称 | バージョン | 特徴 | 判定 |
| --- | --- | --- | --- | --- |
| 1 | 使わない（自作） | — | Tailwind と HTML 標準の要素で作る | 採用 |
| 2 | shadcn/ui | CLI 4.23.0 | 部品のコードをプロジェクトにコピーする | 次点 |
| 3 | ヘッドレス UI（Radix、React Aria、Base UI） | 1.3.1 / 1.22.1 / 1.9.0 | 見た目のない、動作だけの部品 | 見送り |
| 4 | Mantine / MUI | 9.8.1 / 9.5.0 | 見た目込みの部品が揃う | 見送り |

## 案1: 使わない（自作）

### 概要

UI ライブラリを使わず、Tailwind CSS と HTML 標準の要素で、必要なコンポーネントを自分で作る方法。

### メリット

- 見た目と設計を自由に決められる
- 依存関係が増えない
- 必要な部品だけを作るので、余計なコードがない

### デメリット

- コンボボックスや日付の選択など、複雑な部品のキーボード操作やアクセシビリティを自分で作り込む必要がある
- 部品を作る時間がかかる

## 案2: shadcn/ui

### 概要

Radix などのヘッドレス UI と Tailwind CSS で作られた部品のコードを、CLI でプロジェクトにコピーして使う仕組み。ライブラリとして依存するのではなく、コードを自分のものとして持つ。

### メリット

- Tailwind CSS と相性が良い
- コピーしたコードは自由に書き換えられる
- アクセシビリティが考慮された部品をすぐに使える

### デメリット

- コピーしたコードの保守は自分で行う
- 内部で Radix などのライブラリに依存する

## 案3: ヘッドレス UI（Radix、React Aria、Base UI）

### 概要

見た目を持たず、キーボード操作やアクセシビリティなどの動作だけを提供する部品のライブラリ。見た目は Tailwind などで自分で付ける。

### メリット

- 複雑な部品の動作とアクセシビリティを任せられる
- 見た目は自由に決められる

### デメリット

- ライブラリへの依存が増える
- 部品ごとの API を覚える必要がある

## 案4: Mantine / MUI

### 概要

見た目込みの部品が一通り揃った、React の UI ライブラリ。

### メリット

- 部品が揃っていて、すぐに画面を作れる
- 日付の選択などの複雑な部品もある

### デメリット

- ライブラリの見た目から離れたデザインにするのが難しい
- 独自のスタイルの仕組みがあり、Tailwind CSS と役割が重なる
- 依存関係が大きい
