# 0010. E2E テスト

## 決定

Playwright を採用する。最初の画面と API がつながった段階で導入し、主要な操作の流れ（例: Toggl のデータ取り込み → 一覧表示）に絞って少数だけ書く。テストは `frontend/e2e` に置き、`docker compose up` と Playwright の `webServer` 設定で環境を起動する。

### 理由

- Chromium・Firefox・WebKit の主要 3 ブラウザを、追加費用なしで検証できる
- 自動で待機する仕組みがあり、不安定なテストが起きにくい
- 並列実行、トレースビューアー、テストの自動生成（codegen）が無料で付く
- `webServer` 設定で、テスト前に dev サーバーを自動で起動できる
- E2E は書き直しのコストが大きいため、少数に絞り、細かい分岐は Vitest（[0009](0009-frontend-test.md)）で確認する

## 比較案

| 案 | 名称 | バージョン | 特徴 | 判定 |
| --- | --- | --- | --- | --- |
| 1 | Playwright | 1.65.1 | 主要 3 ブラウザ、並列実行が無料 | 採用 |
| 2 | Cypress | 16.3.0 | GUI で書きやすい | 見送り |
| 3 | WebdriverIO | 10.2.0 | WebDriver 標準、モバイル対応 | 見送り |
| 4 | Selenium | 4.52.0 | 歴史が長く多言語対応 | 見送り |

## 案1: Playwright

### 概要

Microsoft 製のブラウザ自動化・E2E テストのフレームワーク。

### メリット

- 主要 3 ブラウザに対応している
- 自動待機、並列実行、トレースビューアー、codegen が標準で付く

### デメリット

- ブラウザ本体のダウンロードが必要（数百 MB）

## 案2: Cypress

### 概要

ブラウザの中でテストを実行する E2E テストのフレームワーク。GUI で操作を見ながらテストを書ける。

### メリット

- 画面を見ながらテストを書ける GUI が使いやすい

### デメリット

- WebKit（Safari）への対応は実験的
- 並列実行は有償サービスが前提

## 案3: WebdriverIO

### 概要

WebDriver 標準に準拠した、Node 製のテスト自動化フレームワーク。

### メリット

- モバイルアプリのテストにも広げられる

### デメリット

- 設定が多く、Web だけなら Playwright より手間がかかる

## 案4: Selenium

### 概要

WebDriver によるブラウザ自動化の、最も歴史の長いツール。

### メリット

- Java など多言語で書ける

### デメリット

- 待機処理などを自分で書く必要があり、テストが不安定になりやすい
