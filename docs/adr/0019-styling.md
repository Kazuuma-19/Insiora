# 0019. スタイリング

## 決定

Tailwind CSS だけを使う。Vite には `@tailwindcss/vite` プラグインで組み込む。CSS ファイルは Tailwind の読み込みとテーマの定義（`@theme` での色やフォントなど）に限り、コンポーネントのスタイルはクラスで書く。条件付きのクラスの結合には `clsx` を使う。

### 理由

- スタイルをコンポーネントの中に書けるので、別の CSS ファイルとの行き来やクラス名を考える手間がない
- 色、余白、文字サイズなどをテーマで一元管理でき、画面ごとにばらつかない
- 使ったクラスだけが CSS に出力され、CSS のサイズが大きくならない
- UI ライブラリを使わない（[0020](0020-ui-components.md)）ため、自分でスタイルを書く量が多く、書く速さが重要
- 実行時の処理がないので、CSS-in-JS のような実行時のコストがない

| 案 | 名称 | バージョン | 特徴 | 判定 |

| 1 | Tailwind CSS | 4.3.5 | ユーティリティクラスで書く | 採用 |

## 案1: Tailwind CSS

### 概要

`flex`、`p-4`、`text-sm` のような小さなクラスを組み合わせて、HTML の上で直接スタイルを書く CSS フレームワーク。v4 からは CSS の中でテーマを定義する。

### メリット

- スタイルをコンポーネントの中に書け、クラス名を考える必要がない
- テーマで色や余白を一元管理できる
- 使ったクラスだけが出力される
- 利用者と情報が多い

### デメリット

- クラスが長くなり、HTML が読みにくくなることがある
- クラスの並び順の自動整形は、Prettier のプラグイン（`prettier-plugin-tailwindcss`）が一般的で、oxfmt（[0006](0006-frontend-formatter.md)）で同じことができるかは確認が必要

## 案2: CSS Modules

### 概要

通常の CSS ファイルをコンポーネントごとに書き、クラス名を自動でコンポーネント単位に閉じ込める仕組み。Vite が標準で対応している。

### メリット

- 通常の CSS をそのまま書け、追加のツールが不要
- HTML がクラスで長くならない

### デメリット

- CSS ファイルとコンポーネントを行き来する必要がある
- 色や余白の統一は、CSS 変数などで自分で管理する

## 案3: Panda CSS / vanilla-extract

### 概要

TypeScript でスタイルを書き、ビルド時に CSS を生成するツール。

### メリット

- スタイルが型付きで、テーマの値の間違いがコンパイル時に分かる
- 実行時のコストがない

### デメリット

- 独自の書き方を覚える必要がある
- 利用者と情報が Tailwind より少ない

## 案4: styled-components / Emotion

### 概要

JavaScript の中で CSS を書き、実行時にスタイルを生成する CSS-in-JS のライブラリ。

### メリット

- props に応じてスタイルを動的に変えやすい

### デメリット

- 実行時にスタイルを生成するため、性能のコストがある
- React の新しい描画の仕組み（Server Components など）との相性に制約がある
