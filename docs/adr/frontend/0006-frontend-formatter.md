# 0006. フロントエンドのフォーマッター

## 決定

oxfmt を採用する。

### 理由

- リンター（[0005](0005-frontend-linter.md)）と同じ Oxc 系に揃えられる
- 非常に速く、pre-commit で毎回実行しても待ち時間が少ない
- Prettier に近い整形結果を目指しているため、問題が出ても Prettier への切り替えが容易

## 比較案

| 案 | 名称 | バージョン | 特徴 | 判定 |
| --- | --- | --- | --- | --- |
| 1 | oxfmt | 0.79.0 | Oxc 系、1.0 前 | 採用 |
| 2 | Prettier | 3.10.1 | 標準的、安定版 | 次点 |
| 3 | Biome | 2.6.8 | リンターと一体 | 見送り |

## 案1: oxfmt

### 概要

Oxc プロジェクトの Rust 製フォーマッター。Prettier に近い整形結果を目指している。

### メリット

- oxlint と同じ Oxc 系で、ツールの系統を揃えられる
- 非常に速い

### デメリット

- 1.0 前で、仕様や整形結果が変わる可能性がある

## 案2: Prettier

### 概要

JavaScript / TypeScript / CSS などの標準的なフォーマッター。

### メリット

- 安定版で、エディタ連携や情報が最も多い
- oxlint は書式ルールを持たないので競合しない

### デメリット

- oxfmt や Biome より遅い

## 案3: Biome

### 概要

フォーマッターとリンターを 1 つにまとめた Rust 製のツール。フォーマッターだけを使うこともできる。

### メリット

- 速く、安定している

### デメリット

- リンター（oxlint）と別系統のツールを 2 つ持つことになる
