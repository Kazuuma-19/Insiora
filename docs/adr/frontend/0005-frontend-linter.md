# 0005. フロントエンドのリンター

## 決定

oxlint を採用する。

### 理由

- Vite（Rolldown / Oxc）と同じ Oxc 系のツールで、ツールチェーンの系統を揃えられる
- 非常に速く、pre-commit で毎回実行しても待ち時間が少ない
- React、React Hooks、TypeScript の主要なルールを内蔵していて、プラグインの追加や設定が少なくて済む
- フォーマッター（[0006](0006-frontend-formatter.md)）も同じ Oxc 系の oxfmt にできる

## 比較案

| 案 | 名称 | バージョン | 特徴 | 判定 |
| --- | --- | --- | --- | --- |
| 1 | oxlint | 1.94.0 | Oxc 系、Rust 製で高速 | 採用 |
| 2 | ESLint | 10.15.0 | 事実上の標準、プラグインが豊富 | 次点 |
| 3 | Biome | 2.6.8 | フォーマッターと一体 | 見送り |

## 案1: oxlint

### 概要

Oxc プロジェクトの Rust 製リンター。ESLint 互換のルールを多く内蔵している。

### メリット

- 非常に速い
- React、React Hooks、TypeScript などのルールを内蔵し、設定が少なくて済む

### デメリット

- ESLint のプラグインがすべて使えるわけではない
- 型情報を使うルールには別パッケージが必要

## 案2: ESLint

### 概要

JavaScript / TypeScript の標準的なリンター。プラグインでルールを追加できる。

### メリット

- プラグインと情報が最も多い
- `eslint-plugin-react-hooks` や `typescript-eslint` など、公式のルールが揃う

### デメリット

- oxlint より遅い
- 設定が多い

## 案3: Biome

### 概要

フォーマッターとリンターを 1 つにまとめた Rust 製のツール。

### メリット

- フォーマッターと一体になっていて、速い

### デメリット

- oxlint と役割が重複する
- ESLint のプラグインは使えない
