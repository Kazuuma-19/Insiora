# 0016. DB アクセス

## 決定

Spring Framework の `JdbcClient` を採用する。SQL を直接書き、結果は Java の record にマッピングする。Spring Data JDBC のリポジトリは使わないため、依存関係は `spring-boot-starter-data-jdbc` から `spring-boot-starter-jdbc`（テストは `spring-boot-starter-jdbc-test`）に変更する。

### 理由

- Insiora は Toggl の時間記録の集計（期間別、プロジェクト別、タグ別など）が中心で、集計 SQL（`GROUP BY`、ウィンドウ関数、PostgreSQL 固有の関数）を制約なく書きたい
- ORM やリポジトリを使っても、集計クエリは結局 SQL を書くことになり、利点が小さい
- Spring 標準の機能で、追加のライブラリや、スキーマからのコード生成が不要
- 暗黙の動作（遅延読み込み、変更の自動検知など）がなく、実行される SQL がコードから分かる
- SQL の誤りは、Testcontainers のテスト（[0008](0008-backend-test.md)）で検出する

## 比較案

| 案 | 名称 | バージョン | 特徴 | 判定 |
| --- | --- | --- | --- | --- |
| 1 | JdbcClient | Spring Framework 標準 | SQL を直接書く、メソッドチェーンの API | 採用 |
| 2 | Spring Data JDBC | Boot 管理 | リポジトリで単純な CRUD | 見送り |
| 3 | Spring Data JPA（Hibernate） | Hibernate 7.4.13（Boot 管理） | ORM、機能が豊富 | 見送り |
| 4 | jOOQ | 3.21.9（Boot 管理） | 型安全な SQL の組み立て | 次点 |
| 5 | MyBatis | mybatis-spring-boot-starter 4.1.0 | SQL を XML などで管理 | 見送り |

## 案1: JdbcClient

### 概要

Spring Framework 6.1 で追加された、`JdbcTemplate` をメソッドチェーンで使いやすくした API。SQL を書いて実行し、結果をオブジェクトにマッピングする。

### メリット

- SQL をそのまま書けるので、集計クエリを制約なく使える
- 名前付きパラメーター（`:from`、`:to`）が使える
- 結果を record に直接マッピングできる
- Spring 標準の機能で、仕組みが単純で、学習コストが低い

### デメリット

- SQL は文字列のため、カラム名の間違いなどは実行するまで分からない
- 単純な登録・更新・削除も SQL を書く必要がある
- エンティティの関連（1 対多など）は自分でマッピングする

## 案2: Spring Data JDBC

### 概要

Spring Data のリポジトリの仕組みを、JDBC で実現するライブラリ。集約（Aggregate）単位でデータを読み書きする。

### メリット

- リポジトリのインターフェースだけで、単純な登録・更新・削除ができる
- JPA より単純で、遅延読み込みなどの暗黙の動作がない

### デメリット

- 集計クエリは結局 `@Query` で SQL を書くことになる
- 集約単位の設計に従う必要があり、集計中心のアプリでは利点が小さい

## 案3: Spring Data JPA（Hibernate）

### 概要

Java の ORM 標準（JPA）を、Hibernate で実装したもの。エンティティとテーブルを対応させ、オブジェクトとして読み書きする。

### メリット

- 利用者と情報が最も多い
- エンティティの関連や変更の自動検知など、機能が豊富

### デメリット

- 遅延読み込み、N+1 問題、永続化コンテキストなど、暗黙の動作を理解する必要がある
- 複雑な集計は JPQL では書きにくく、ネイティブ SQL を使うことになる

## 案4: jOOQ

### 概要

DB のスキーマから Java のコードを生成し、SQL を Java の DSL で型安全に組み立てるライブラリ。

### メリット

- カラム名の間違いがコンパイル時に分かる
- 集計クエリも表現できる

### デメリット

- スキーマからのコード生成（DB への接続か、Flyway との連携）が必要で、ビルドが複雑になる
- jOOQ 独自の DSL を覚える必要がある
- PostgreSQL は無料版で使えるが、一部の商用 DB は有償

## 案5: MyBatis

### 概要

SQL を XML やアノテーションで定義し、結果をオブジェクトにマッピングするライブラリ。

### メリット

- 動的 SQL が書きやすい

### デメリット

- Spring 標準ではなく、追加のライブラリと設定が必要
- SQL をそのまま書くという点では JdbcClient と変わらず、追加の利点が小さい
