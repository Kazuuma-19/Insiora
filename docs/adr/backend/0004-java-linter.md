# 0004. Java のリンター

## 決定

Error Prone を採用する。

### 理由

- 書式はフォーマッター（[0003](0003-java-formatter.md)）が揃えるため、リンターはバグ検出に絞る
- コンパイルのたびに動くので、別の工程として実行し忘れることがない
- プロジェクト全体の検査は Qodana（[0007](0007-static-analysis.md)）が担うため、SpotBugs や PMD は重複する
- null の検査は、Error Prone のプラグインの NullAway（[0017](0017-null-safety.md)）で行う

## 比較案

| 案 | 名称 | バージョン | 特徴 | 判定 |
| --- | --- | --- | --- | --- |
| 1 | Error Prone | 2.52.0 | コンパイル時にバグを検出 | 採用 |
| 2 | SpotBugs | 4.10.5 | バイトコードを解析 | 見送り |
| 3 | PMD | 7.29.0 | コードの臭いを検出 | 見送り |
| 4 | Checkstyle | 14.4.0 | スタイルを検査 | 見送り |

## 案1: Error Prone

### 概要

Google 製の Java コンパイラーのプラグイン。コンパイル時に、よくあるバグのパターンを検出してエラーや警告にする。

### メリット

- equals の誤用、無視された戻り値などのバグを、コンパイルのたびに検出する
- 別の工程として実行する必要がない

### デメリット

- コンパイラーのプラグインのため、Java のバージョンへの対応を確認する必要がある

## 案2: SpotBugs

### 概要

コンパイル後のバイトコードを解析し、バグのパターンを検出するツール。

### メリット

- null 参照などのバグを検出する

### デメリット

- Error Prone や Qodana と検出範囲が一部重なる
- 実行に時間がかかる

## 案3: PMD

### 概要

ソースコードを解析し、未使用のコードや複雑すぎるメソッドなどのコードの臭いを検出するツール。

### メリット

- 保守性に関わる問題を検出できる

### デメリット

- ルールの取捨選択が必要
- Qodana と検出範囲が一部重なる

## 案4: Checkstyle

### 概要

命名規則や書式などのコーディングスタイルを検査するツール。

### メリット

- スタイルを細かく検査できる

### デメリット

- 書式はフォーマッターが自動で揃えるため、多くのルールが重複する
