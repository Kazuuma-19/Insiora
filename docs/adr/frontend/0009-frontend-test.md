# 0009. frontend のテスト

## 決定

テストランナーに Vitest、コンポーネントのテストに React Testing Library、ブラウザ環境に jsdom を採用する。

### 理由

- Vite の設定（`vite.config.ts`）をそのまま使え、テスト用の設定を別に持たなくてよい
- TypeScript と ESM が追加の設定なしで動く
- Jest とほぼ同じ書き方で、情報を流用できる
- React Testing Library は、実装の詳細ではなく利用者の操作に近い形でテストでき、リファクタリングに強い

## 比較案

| 案 | 名称 | バージョン | 特徴 | 判定 |
| --- | --- | --- | --- | --- |
| 1 | Vitest | 5.1.0 | Vite の設定を共有 | 採用 |
| 2 | Jest | 30.5.2 | 歴史が長く実績が多い | 見送り |

## 案1: Vitest

### 概要

Vite をベースにしたテストランナー。Jest と互換性の高い API を持つ。

### メリット

- `vite.config.ts` の設定をそのまま使える
- TypeScript が追加の設定なしで動く
- Jest とほぼ同じ書き方ができる

### デメリット

- Jest に比べると、情報や実績はまだ少ない

## 案2: Jest

### 概要

Meta 製の、JavaScript の標準的なテストランナー。

### メリット

- 歴史が長く、実績と情報が多い

### デメリット

- Vite や ESM と組み合わせるには、追加の設定が必要
