# 0013. サーバーデータの取得

## 決定

TanStack Query を採用する。フックは orval（[0012](0012-frontend-codegen.md)）で生成する。

### 理由

- Insiora では「Toggl と同期したらすべてのグラフが変わる」「設定を変えたら集計も変わる」ように、1 つの更新が複数のデータに影響する
- `invalidateQueries({ queryKey: ['summary'] })` のように、関連するデータを前方一致でまとめて取得し直せる
- `useMutation` は特定のキーに結び付かず、成功・失敗などの各タイミングで複数のデータを扱える
- 期間を切り替えて見る画面が多く、`staleTime` と `gcTime` でキャッシュを細かく調整できる
- 公式の DevTools で、キャッシュの状態を画面で確認できる

## 比較案

| 案 | 名称 | バージョン | 特徴 | 判定 |
| --- | --- | --- | --- | --- |
| 1 | TanStack Query | 5.108.0 | 更新とキャッシュの管理が充実 | 採用 |
| 2 | SWR | 2.5.1 | 小さく軽い | 次点 |
| 3 | RTK Query | Redux Toolkit 2.14.0 | Redux と統合 | 見送り |
| 4 | React Router の loader | react-router 8.5.1 | 画面遷移と同時に取得 | 見送り |
| 5 | ライブラリを使わない | — | `use` + Suspense、`useEffect` + fetch | 見送り |

## 案1: TanStack Query

### 概要

サーバーのデータの取得、キャッシュ、更新、再取得を管理するライブラリ。

### メリット

- キーの前方一致で、関連データをまとめて取得し直せる
- `useMutation` の各タイミングで、複数のデータを扱える
- `MutationCache` に共通のエラー処理を 1 回書けば、全体に効く
- 公式の DevTools がある

### デメリット

- 機能が多く、`queryKey` の設計など覚えることが多い
- バンドルサイズが SWR より大きい

## 案2: SWR

### 概要

Vercel 製の、データ取得とキャッシュのためのライブラリ。名前は「stale-while-revalidate」に由来する。

### メリット

- API が小さく、覚えることが少ない
- 軽い
- 取得して表示するだけなら十分

### デメリット

- `useSWRMutation` は 1 つのキーに結び付き、ほかのデータは個別に更新する必要がある
- まとめて取得し直すには、対象のキーを判定する関数を自分で書く
- 公式の DevTools がない

## 案3: RTK Query

### 概要

Redux Toolkit に含まれる、データ取得とキャッシュのための機能。

### メリット

- キャッシュも Redux の状態として扱える

### デメリット

- Redux を使わないなら、仕組みとして重い
- orval が対応していない

## 案4: React Router の loader

### 概要

React Router のルートごとに、画面を表示する前にデータを取得する仕組み。

### メリット

- 画面遷移と同時にデータを取得できる

### デメリット

- キャッシュや再取得の機能が限られる

## 案5: ライブラリを使わない

### 概要

React 19 の `use` と Suspense、または `useEffect` と fetch で、データを直接取得する方法。

### メリット

- 依存関係が増えない

### デメリット

- キャッシュ、競合状態、エラー時の再試行などを自分で書く必要がある
