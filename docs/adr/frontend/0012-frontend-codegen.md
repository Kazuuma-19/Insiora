# 0012. frontend のコード生成

## 決定

orval を採用する。

### 理由

- データ取得に TanStack Query（[0013](0013-data-fetching.md)）を使うため、フックを生成できると画面でそのまま使える
- API のモックに MSW（[0015](0015-api-mock.md)）を使うため、ハンドラーも同時に生成できる
- 型・フック・モックが 1 回の生成で揃い、ツールを組み合わせる必要がない

## 比較案

| 案 | 名称 | バージョン | 特徴 | 判定 |
| --- | --- | --- | --- | --- |
| 1 | orval | 8.48.0 | 型・フック・MSW のモックを生成 | 採用 |

## 案1: orval

### 概要

OpenAPI から、TypeScript の型、API 関数、TanStack Query や SWR のフック、MSW のモック、Zod のスキーマを生成するツール。

### メリット

- 必要なものを 1 回で生成できる
- 生成したフックをそのまま画面で使える

### デメリット

- 生成されるコードと設定項目が多い

## 案2: openapi-typescript + openapi-fetch

### 概要

openapi-typescript で OpenAPI から型だけを生成し、openapi-fetch という小さなクライアントで型付きの呼び出しをする構成。

### メリット

- 生成物は型だけで、最も軽量
- パスや引数まで型チェックされる

### デメリット

- フックやモックは自分で用意する必要がある

## 案3: @hey-api/openapi-ts

### 概要

OpenAPI から型と SDK を生成し、プラグインで TanStack Query や Zod などの出力を追加できるツール。

### メリット

- プラグインで出力を選べ、生成コードが読みやすい

### デメリット

- 1.0 前で、更新のたびに破壊的変更が入りやすい

## 案4: Kubb

### 概要

プラグインを組み合わせて、OpenAPI から型、フック、モックなどを生成するツール。

### メリット

- 出力を細かく作り込める

### デメリット

- 設定が重く、小規模な開発には過剰

## 案5: @typespec/http-client-js

### 概要

TypeSpec の定義から、直接 TypeScript のクライアントを生成する公式の emitter。

### メリット

- OpenAPI を経由しない

### デメリット

- 0.x の段階
- backend は OpenAPI が必要なので、生成元が 2 系統になる
